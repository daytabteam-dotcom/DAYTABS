Read all existing auth, database, and API route files carefully before starting.

─────────────────────────────────────────
1. DATABASE SCHEMA — USAGE TRACKING
─────────────────────────────────────────
Create or update the database to track usage per user per billing period.

Add a `user_usage` table (or collection) with these fields:
  - user_id (foreign key to users table)
  - period_start (date — first day of current billing month)
  - period_end (date — last day of current billing month)
  - video_analyses_used (integer, default 0)
  - script_planner_chats_used (integer, default 0)
  - last_updated (timestamp)

Add a `user_plans` table if it doesn't exist:
  - user_id
  - plan_name (enum: 'free', 'creator', 'pro', 'studio')
  - plan_started_at (timestamp)
  - plan_expires_at (timestamp, nullable — null means active)
  - is_active (boolean)

Reset usage counters automatically at the start of each billing month.
The reset logic: when a usage check is made, if period_start is in a 
previous month, reset counters to 0 and update period_start/period_end 
to the current month before checking limits.

3. ENFORCEMENT MIDDLEWARE
─────────────────────────────────────────
Create a reusable middleware function called `checkLimit` that runs 
BEFORE any analysis or script planner API call.

It must check in this exact order:

STEP 1 — Authentication
  If user is not logged in:
  → Return 401
  → Error code: AUTH_REQUIRED
  → Message: "Please sign in to continue."

STEP 2 — Plan lookup
  Fetch user's current plan from user_plans table.
  If no plan found, default to 'free'.

STEP 3 — Monthly reset check
  If period_start is in a previous month:
  → Reset video_analyses_used = 0
  → Reset script_planner_chats_used = 0
  → Update period_start and period_end to current month

STEP 4 — Feature access check
  If the requested feature is not enabled for the user's plan:
  → Return 403
  → Error code: FEATURE_LOCKED
  → Message: specific per feature (see section 4)
  → Include: { upgrade_to: 'creator' } (or whichever plan unlocks it)

STEP 5 — Video file size check (for upload routes only)
  If file size exceeds plan limit:
  → Return 413
  → Error code: FILE_TOO_LARGE
  → Message: specific (see section 4)

STEP 6 — Video duration check (after duration is known)
  If video duration exceeds plan limit:
  → Return 422
  → Error code: VIDEO_TOO_LONG
  → Message: specific (see section 4)

STEP 7 — Monthly usage limit check
  If video_analyses_used >= plan limit:
  → Return 429
  → Error code: MONTHLY_LIMIT_REACHED
  → Message: specific (see section 4)
  → Include: { used: X, limit: Y, resets_on: date }

STEP 8 — Script planner chat limit (for script planner routes only)
  If script_planner_chats_used >= plan limit:
  → Return 429
  → Error code: CHAT_LIMIT_REACHED
  → Message: specific (see section 4)

STEP 9 — If all checks pass:
  → Increment the relevant counter
  → Proceed with the request

5. COUNTER ROLLBACK ON FAILURE
─────────────────────────────────────────
If an analysis is started (counter incremented) but fails before 
completing due to a server error or API error:
- Decrement video_analyses_used by 1
- Log the failure with: user_id, timestamp, error_type, job_id
- Show GENERIC_ERROR to the user
- Never charge a failed analysis against the user's monthly limit

6. FRONTEND ERROR HANDLING
─────────────────────────────────────────
Create a reusable ErrorModal component that handles all error states.

The modal must:
- Show the title and message from the error response
- Show the primary action button (styled with the existing purple theme)
- Show secondary action if present (styled as text link)
- For MONTHLY_LIMIT_REACHED: show a mini plan comparison

- For FEATURE_LOCKED: show a one-line preview of what they're missing
- Never show error codes or stack traces to the user
- Be dismissible with ESC key or clicking outside
- On the pricing page link, highlight the recommended upgrade plan 
  automatically using URL param: /pricing?highlight=creator

Also add inline limit indicators in the dashboard:
- Show "X / Y analyses used this month" progress bar on home dashboard
- Show "X / Y script chats used" in Script Planner sidebar
- When usage reaches 80%, change progress bar color to amber
- When usage reaches 100%, change to red and disable the 
  relevant action button with a tooltip showing reset date
