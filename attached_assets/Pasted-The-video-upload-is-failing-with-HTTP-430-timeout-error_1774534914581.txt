The video upload is failing with HTTP 430/timeout errors on large files.
The entire upload pipeline needs to be rebuilt using chunked uploading.
Read all existing upload route and frontend upload code carefully first.

─────────────────────────────────────────
1. ROOT CAUSE
─────────────────────────────────────────
The current upload sends the entire video file in one HTTP request.
This fails because:
- Replit has a request timeout (~30 seconds)
- Large files exceed memory buffer limits
- A single failed request means starting over completely

The fix is to split the file into small chunks on the frontend,
upload each chunk separately, then reassemble on the server.
This way no single request is large or slow enough to timeout.

─────────────────────────────────────────
2. FRONTEND — CHUNKED UPLOAD
─────────────────────────────────────────
Replace the current upload logic with this chunked approach:

CHUNK SIZE: 5MB per chunk (5 * 1024 * 1024 bytes)
This is small enough to never timeout even on slow connections.

Implementation:

const CHUNK_SIZE = 5 * 1024 * 1024; // 5MB

async function uploadVideoInChunks(file, onProgress) {
  const totalChunks = Math.ceil(file.size / CHUNK_SIZE);
  
  // Step 1: Initialize upload session on server
  const initRes = await fetch('/api/upload/init', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      filename: file.name,
      fileSize: file.size,
      mimeType: file.type,
      totalChunks: totalChunks
    })
  });
  const { uploadId } = await initRes.json();

  // Step 2: Upload each chunk sequentially
  for (let chunkIndex = 0; chunkIndex < totalChunks; chunkIndex++) {
    const start = chunkIndex * CHUNK_SIZE;
    const end = Math.min(start + CHUNK_SIZE, file.size);
    const chunk = file.slice(start, end);

    const formData = new FormData();
    formData.append('chunk', chunk);
    formData.append('uploadId', uploadId);
    formData.append('chunkIndex', chunkIndex.toString());
    formData.append('totalChunks', totalChunks.toString());

    let attempts = 0;
    let success = false;

    // Retry each chunk up to 3 times on failure
    while (attempts < 3 && !success) {
      try {
        const res = await fetch('/api/upload/chunk', {
          method: 'POST',
          body: formData
        });
        if (!res.ok) throw new Error('Chunk failed');
        success = true;
      } catch (err) {
        attempts++;
        if (attempts === 3) throw new Error(
          `Chunk ${chunkIndex} failed after 3 attempts`
        );
        // Wait 1 second before retry
        await new Promise(r => setTimeout(r, 1000));
      }
    }

    // Report progress
    const progress = Math.round(((chunkIndex + 1) / totalChunks) * 100);
    onProgress(progress);
  }

  // Step 3: Tell server to assemble chunks
  const completeRes = await fetch('/api/upload/complete', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ uploadId })
  });
  const { filePath } = await completeRes.json();
  return { uploadId, filePath };
}

3. BACKEND — THREE NEW UPLOAD ROUTES
─────────────────────────────────────────
Create these three routes to handle chunked uploads:

POST /api/upload/init
  Body: { filename, fileSize, mimeType, totalChunks }
  
  Actions:
  - Run plan limit checks (auth, file size, monthly limit)
  - Generate a unique uploadId (uuid)
  - Create a temp directory: /tmp/uploads/{uploadId}/
  - Store upload metadata in memory or DB:
    { uploadId, userId, filename, totalChunks, 
      chunksReceived: 0, createdAt: Date.now() }
  - Return: { uploadId }
  
  Reject immediately if:
  - File size exceeds plan limit → FILE_TOO_LARGE error
  - User has no analyses remaining → MONTHLY_LIMIT_REACHED error
  - File type not allowed (only mp4, mov, avi, webm, mkv)
    → { error: 'INVALID_FILE_TYPE', 
        message: 'Please upload a video file (MP4, MOV, AVI, WebM)' }

POST /api/upload/chunk
  Body: FormData with { chunk (binary), uploadId, 
                        chunkIndex, totalChunks }
  
  Actions:
  - Validate uploadId exists and belongs to current user
  - Write chunk to: /tmp/uploads/{uploadId}/chunk_{chunkIndex}
  - Update chunksReceived counter
  - Return: { received: chunkIndex, total: totalChunks }
  
  Constraints:
  - Max chunk size: 6MB (reject anything larger)
  - Validate chunkIndex is a valid number
  - If uploadId doesn't exist: return 404 
    (session expired or invalid)

POST /api/upload/complete
  Body: { uploadId }
  
  Actions:
  - Verify all chunks received 
    (chunksReceived === totalChunks)
  - Assemble chunks in order:
    Read chunk_0, chunk_1, ... chunk_N
    Write to: /tmp/uploads/{uploadId}/{filename}
    Delete individual chunk files after assembly
  - Get video duration using ffprobe:
    ffprobe -v quiet -print_format json 
            -show_format /tmp/uploads/{uploadId}/{filename}
  - Check duration against plan limit → VIDEO_TOO_LONG if exceeded
  - Hand off to existing analysis pipeline with the file path
  - Increment video_analyses_used counter NOW 
    (after duration check passes, before pipeline starts)
  - Return: { uploadId, filePath, duration }

8. SERVER CONFIGURATION
─────────────────────────────────────────
Update server config to handle chunked uploads properly:

Express/Node settings:
  - Set body-parser limit to 10MB for chunk route only:
    app.use('/api/upload/chunk', express.raw({ limit: '10mb' }))
  - For other routes keep existing limits
  - Set timeout for chunk route to 60 seconds:
    req.setTimeout(60000)

Make sure /tmp directory is writable on Replit:
